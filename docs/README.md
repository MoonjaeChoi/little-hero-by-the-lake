# 잭팟 ARPG 게임 디자인 설계서

> 장비 시스템 중심의 풀스택 설계 가이드
> 메이플스토리의 깊이 + 디아블로의 빌드 다양성 + 탕탕특공대의 진행 명확성
>
> 브레인스토밍 결과 정리 · 파트별 후속 설계용

---

## 문서 사용 안내

이 문서는 게임 디자인 브레인스토밍 결과를 정리한 작업용 설계서입니다. 8개 파트로 구성되어 있으며, 각 파트는 독립적으로 후속 설계를 진행할 수 있도록 일관된 구조를 가집니다.

### 각 파트의 구조

1. **핵심 결정** — 이미 합의된 방향과 그 이유
2. **설계 원칙** — 결정의 근거가 되는 원칙들
3. **구체적 사양** — 숫자, 공식, 데이터 모델 등 즉시 구현 가능한 세부 내용
4. **미해결 질문** — 다음 단계에서 결정해야 할 항목
5. **다음 단계** — 이 파트를 더 구체화하기 위한 구체적인 작업

---

## 3대 설계 철학

> 모든 후속 결정의 기준. 새 기능이 이 철학과 충돌한다면, 기능을 다시 검토하거나 원칙을 명시적으로 예외 처리한다.

1. **결정론적 진행 위에 잭팟을 쌓는다** — 갈면 무조건 오르는 바닥을 보장한 위에 RNG 잭팟을 두어, 노력의 좌절을 차단하면서 도파민은 살린다.
2. **단일 진실원에서 모든 것을 흐르게 한다** — 모든 게임 상태는 서버 권위, 모든 도메인은 단일 쓰기 경로, 모든 효과는 같은 데이터 형태.
3. **콘텐츠는 데이터로 관리한다** — 신화 옵션, 세트, 시즌 메타가 모두 마스터 데이터의 row로 표현되어 운영팀이 코드 배포 없이 메타를 회전시킬 수 있다.

## 이 문서 이후의 작업 순서 (요약)

1. **Part 0 보강** — 게임 컨셉 1페이지, 핵심 게임플레이 루프
2. **Part 1 보강** — 클래스 구조, 슬롯 카탈로그
3. **Part 2~4 병행** — 강화 비용 곡선, 재화 카탈로그, archetype 정의, 신화·세트 카탈로그
4. **Part 5 보강** — 디자인 시스템, 핵심 화면 와이어프레임
5. **Part 7 보강** — API 스펙, 인프라 견적, CI/CD 파이프라인
6. **Phase 1 알파 진입** — 코어 루프만 구현해 검증

> Part 2~4는 서로 강하게 얽혀있어 병행하면서 자주 동기화하는 것이 좋다.

## 메모: 기존 프로젝트와의 관계

이 설계서는 게임의 **방향 대폭 수정** 결과로 도입됐다. 기존 `CLAUDE.md`의 "Little Hero by the Lake" (Auto-Shooter Roguelite, Unity, 키즈) 설계는 별개 프로젝트로 보존되며, 이 문서가 다루는 잭팟 ARPG와는 장르·플랫폼·타겟이 다르다. 두 방향의 통합/분리 결정은 향후 별도로 진행한다.
