## 1. 핵심 결정

### 아이템 카드의 정보 위계 5단

플레이어의 시선 동선이 의사결정 동선이 되도록 위에서 아래로 다음 순서로 배치한다.

| 순서 | 영역 | 역할 |
|---|---|---|
| 1 | 정체성 | 아이콘, 이름, 등급, 강화 단계 — 한눈에 정체 파악 |
| 2 | 히어로 스탯 | 메인 스탯을 36px로 큼직하게 — 강화 도파민의 핵심 |
| 3 | 강화 영역 | 회색 배경으로 분리, 천장 게이지 + 강화 버튼 |
| 4 | 옵션 영역 | 잠금/미잠금 시각 구분, 리롤 버튼 (비용 표시) |
| 5 | 신화 영역 | 보라색 배경으로 명확히 구분 — 잭팟의 영광 |

## 2. 설계 원칙

### 플랫폼별 정보 밀도

같은 데이터를 PC와 모바일에서 다른 밀도로 제공하되, **백엔드 응답은 동일하게 유지**한다.

**PC 3단계**:
- **인벤토리 그리드** (가장 압축) — 아이콘 + 강화 단계만, 신화 보유 시 보라 테두리
- **호버 툴팁** (중간 밀도) — 이름 + 등급 + 메인 스탯 + 옵션 3줄 + 신화, 액션 버튼 없음
- **클릭 시 측면 패널** (모바일과 동일) — 강화/리롤 버튼 포함

**모바일**:
- 풀스크린 카드 — PC의 측면 패널과 동일 컴포넌트
- 스와이프로 다른 아이템과 비교

### 강화 결과 연출 — 1초의 도파민 루프

서버 응답이 오면 즉시 카드를 갱신하지 말고, **짧은 로딩 → 결과 애니메이션 → 카드 갱신** 순으로 연출한다. 이 1초가 다음 강화를 누르게 만드는 도파민 루프의 정점.

- **성공**: 히어로 스탯 카운트업, 천장 게이지 0으로 리셋
- **실패**: 천장 게이지 채워짐, 다음 시도 확률 갱신
- **신화 발현**: 보라색 영역이 카드 전체를 잠시 휘감음
- **천장 도달**: 노란빛 번쩍임 + 별도 메시지

서버 응답에 `result_type` enum (`success / fail / mythic_unlocked / pity_triggered`)을 두면 프론트의 애니메이션 분기가 깔끔해진다.

## 3. 구체적 사양

### 단일 API · 다중 UI 패턴

```
GET /items/{id}
응답: ItemDetail (모든 필드 포함)
  ├─ id, name, slot, tier, icon
  ├─ enhance: { level, max_level, fail_count, next_probability, pity_remaining }
  ├─ stats: { primary, secondary[] }
  ├─ affixes: [{ id, label, value, locked }]
  ├─ mythic: { id, name, description } | null
  └─ actions: { can_enhance, can_reroll, reroll_cost }

프론트 컴포넌트:
  <ItemCell item={data} />        // 인벤토리 그리드용
  <ItemTooltip item={data} />     // 호버용
  <ItemDetailPanel item={data} /> // 모바일/PC 패널 공용
```

`actions` 필드를 서버에서 내려주는 점이 핵심. 클라이언트가 비즈니스 룰을 판단하지 않으니 어뷰징 우회가 차단되고, 버튼 비활성화도 단순해진다.

## 4. 미해결 질문

- 정확한 컬러 팔레트 (등급별 색상, 다크 모드 변형)
- 폰트 시스템 (제목, 본문, 숫자 강조용)
- 모션 디자인 — 애니메이션 타이밍, 이징
- 사운드 디자인 — 강화 성공/실패, 신화 발현
- 다크 모드 지원 여부
- 접근성 (색맹 대응, 폰트 크기 조정)
