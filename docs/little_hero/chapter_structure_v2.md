## 1. 핵심 결정

### 새 프레임: 다락방의 신기한 지도

> 어느 비 오는 오후, 작은 영웅은 다락방 깊숙한 곳에서 **빛바랜 지도 한 장**을 발견한다. 지도에는 본 적 없는 장소들이 표시되어 있고, 한 장소를 손가락으로 가리키면 **그 장소의 풍경이 지도 안에서 살아 움직이며** 작은 영웅을 빨아들인다.

- **챕터 = 지도 위의 한 장소**. 서로 무관한 35개 장소.
- **연결 서사 최소** — 이전 v1의 8권 동화 시리즈 직렬 제거.
- **테마 다양성 극대화** — 자연·환상·문명·동물·메타 5분류로 확장.
- **선형 진행** ✦ — 1번부터 35번까지 차례대로 클리어. 챕터 번호↑ = 적 스탯↑.
- **장신구 3-티어 시스템** ✦ — 챕터 6~10 슬롯 해방, 16~20 향상, 26~30 정점. 슬롯 순서는 모든 티어에서 **귀걸이→안경→목걸이→반지→펫** 고정. 자세한 내용 [`equipment_v1.md §3.7`](./equipment_v1.md).

### 이전 v1과의 차이

| 항목 | v1 (폐기) | v2 (적용) |
|---|---|---|
| 프레임 | 동화책 8권 시리즈 | 다락방 신기한 지도 1장 + 35 장소 |
| "책" 단어 사용 | 핵심 컨셉 | **금지** (사용자 결정) |

| 슬롯 해방 | 권 보스 8개 중 5개 | 핵심 5 챕터 (정해진 위치) |

## 2. 설계 원칙

- **메타·기억으로 시작** ✦ — 게임 시작 시 가장 친숙한 환경(호숫가 마을·다락방·학교)부터. 정서 코어 강화.
- **점진적 환상화** — 친숙 → 자연 → 동물 → 문명 → 환상 순서로 환경이 점점 비현실적이 됨.
- **마지막 챕터는 우주 도약** — 35번 = 별과 별 사이. 가장 멀고 어려운 곳.
- **자유 진행은 후속 패치** — MVP는 선형 단일 경로. 향후 분기·자유 진행은 선택 패치 (Dead Cells의 분기 차용은 옵션).
- **컨텐츠는 후속** — 이 문서는 35 챕터의 구조와 보스 배치 placeholder만. 적·보스의 실명·HP·외형은 후속에서.

## 4. 장신구 3-티어 시스템 (15 챕터)

같은 5 슬롯이 **3번 반복**해 향상된 옵션으로 드랍. 슬롯 순서는 모든 티어에서 **귀걸이 → 안경 → 목걸이 → 반지 → 펫** 고정.

### 티어별 챕터 매핑

| 슬롯 | 🟢 티어 1 (해방·시작) | 🟡 티어 2 (향상) | 🟣 티어 3 (정점) |
|---|---|---|---|
| 귀걸이 | 6 안개 골짜기 | 16 새들의 둥지 도시 | 26 음악 동굴 |
| 안경 | 7 깊은 숲 | 17 발광 해파리 정원 | 27 종이 인형 무대 |
| 목걸이 | 8 노래하는 폭포 | 18 고래 노래 바다 | 28 살아있는 정원 |
| 반지 | 9 반딧불 풀밭 | 19 거대 거북이 등 | 29 거울 갤러리 |
| 펫 | 10 모래 회오리 사막 | 20 별빛 늑대 산골 | 30 거대한 시계탑 안 |

### 티어 등급

| 티어 | 챕터 | 드랍 등급 | 장신구 의미 |
|---|---|---|---|
| 🟢 1 | 6~10 | Common | 슬롯 영구 해방 + 첫 장신구 1개 |
| 🟡 2 | 16~20 | Uncommon ~ Rare | 같은 슬롯의 향상된 옵션 |
| 🟣 3 | 26~30 | Rare ~ Epic | 같은 슬롯의 정점 옵션 |

### 적응 구간 (장신구와 무관)

| 묶음 | 챕터 | 역할 |
|---|---|---|
| 1~5 | 메타·기억 | 진입·정서 코어. 주 슬롯 7개로만 진행 |
| 11~15 | 자연·동물 전환 | 티어 1 장신구로 적응 |
| 21~25 | 동물·문명 전환 | 티어 2 장신구로 적응 |
| 31~35 | 환상 정점 | 티어 3 장신구로 최종 도전 |

> 35 챕터 = 선형 진행. 챕터 번호↑ = 적 스탯↑ (§5 곡선). 장신구 드랍 챕터는 **챕터 보상의 시각적 정점** — UI에서 빛나게 강조.

## 5. 적 스탯 곡선 (챕터 번호↑ = 강해짐)

> ✦ 사용자 결정: "순서가 올라갈수록 몬스터의 스탯이 높아지도록"

### 권장 공식 (초안)

```
enemy.maxHealth(chapter N)    = base_hp  × 1.10^(N-1)
enemy.attackDamage(chapter N) = base_dmg × 1.10^(N-1)
enemy.xpDrop(chapter N)       = base_xp  × 1.08^(N-1)
enemy.starDustDrop(chapter N) = base_dust × 1.08^(N-1)
```

### 챕터별 적 스탯 배수 (Common 일반 적 기준)

| 챕터 | 배수 | 권장 캐릭터 레벨 | 권장 강화 단계 | 장신구 |
|---|---|---|---|---|
| 1 (시작) | × 1.0 | 1 | +0 | 없음 |
| 5 | × 1.46 | 5 | +2 | 없음 (메타·기억 끝) |
| 10 (펫 슬롯 🟢) | × 2.36 | 12 | +5 | 5 슬롯 모두 해방 (Common) |
| 15 | × 3.80 | 20 | +8 | Common 유지 |
| 20 (펫 t2 🟡) | × 6.12 | 28 | +11 | 5 슬롯 향상 (Uncommon~Rare) |
| 25 | × 9.85 | 36 | +13 | t2 유지 |
| 30 (펫 t3 🟣) | × 15.86 | 44 | +16 (천장 시작) | 5 슬롯 정점 (Rare~Epic) |
| 35 (마지막) | × 25.55 | 52 | +18~+20 | t3 유지·다듬기 |

> 보스(W20)는 위 배수 + **× 5~10 추가 곱셈**. 미니보스(W5/W10/W15)는 × 2~3 추가.

> 정확한 곡선은 시뮬레이터로 검증 필요. 위 표는 시작점 가설.

## 6. 데이터 모델 변경 사양

### 신규/갱신 SO

```csharp
// 단일 SO — 35개 인스턴스
[CreateAssetMenu(menuName = "LittleHero/Chapter")]
public class ChapterData : ScriptableObject {
    public int chapterNumber;          // 1 ~ 35 (히든은 36)
    public string id;                  // "ch_01_lakeside_village"
    public string displayName;         // "호숫가 작은 마을"
    [TextArea] public string description;
    public Sprite mapIcon;             // 지도 위에 표시될 아이콘

    public ChapterCategory category;   // E/A/D/C/B
    public AccessoryDropTier accessoryTier;  // None/Tier1/Tier2/Tier3
    public string accessoryDropSlot;   // null | "Earring" | "Glasses" | "Necklace" | "Ring" | "Pet"
    public bool unlocksAccessorySlot;  // 티어 1만 true (해방 트리거)
    public bool isHidden;

    public int waveCount = 20;
    public float waveDuration = 20f;
    public EnemyData[] regularEnemyPool;
    public EnemyData[] miniBosses;     // 길이 3 (W5/W10/W15)
    public EnemyData mainBoss;         // W20
    public float enemyStatMultiplier;  // 챕터 번호로 결정 (위 표)

    public int starFragmentReward;
}

public enum ChapterCategory {
    MetaMemory,    // E
    Nature,        // A
    Animal,        // D
    Civilization,  // C
    Fantasy        // B
}

public enum AccessoryDropTier {
    None,    // 일반 챕터 (장신구 없음)
    Tier1,   // 챕터 6~10 (Common, 슬롯 해방)
    Tier2,   // 챕터 16~20 (Uncommon~Rare, 향상)
    Tier3    // 챕터 26~30 (Rare~Epic, 정점)
}
```

> v1의 `BookData` SO는 **불필요**. 챕터를 묶는 권 단위가 사라졌기 때문.

### 진행 추적 (`SaveData`)

```csharp
public int highestUnlockedChapter;   // 1 ~ 35 (시작 = 1)
public int highestClearedChapter;    // 0 ~ 35
public bool[] clearedChapters;       // 길이 36 (히든 포함), 반복 클리어 여부
```

선형 진행이므로 `unlocked = highestCleared + 1` 단순 룰. 핵심 챕터 클리어 시 슬롯 해방은 별도 처리(`unlockedAccessorySlots[]`).

### 마이그레이션 (기존 → v2)

기존 `Chapter_01_RedHood` / `Chapter_02_Beanstalk` / `Chapter_03_Alice` 3개 SO는 **v2 1번 챕터 하나로 흡수**하지 않고, **별개 챕터로 재배치**:
- `Chapter_01_RedHood` → 적·보스 데이터(큰 늑대 등)는 v2의 다른 챕터(예: 7번 깊은 숲)에서 재사용
- `Chapter_02_Beanstalk` → 14번 하늘 구름 다리에서 거인 데이터 재사용
- `Chapter_03_Alice` → 32번 거꾸로 매달린 지하 도시에서 카드 병정·여왕 데이터 재사용
- 마이그레이션은 1회성 + 적 SO는 가능한 한 보존 (`Enemy_BigWolf`·`Enemy_CloudGiant`·`Enemy_QueenHearts` 등 그대로 사용)

- **선형 진행** — 위에서 아래로 한 줄. 다음 챕터만 진입 가능.
- **클리어한 곳**은 황금빛 + 체크마크. 자랑 요소.
- **핵심 챕터**는 ★ 황금 별 마크 + 작은 슬롯 아이콘.
- **현재 선택**은 빛나는 점.
- **미진입**은 흐릿한 점, **잠금**은 자물쇠.

스크롤 가능. 35챕터 = 화면 4~5번 스크롤 분량.
