# Little Hero — 챕터 구조 v1 (메이플 키우기 모델 영감)

> [← Little Hero 인덱스](./README.md) · [장비 v1](./equipment_v1.md)
>
> 기존 5챕터(빨간모자/잭과콩나무/앨리스/헨젤/오즈) 구조가 **장기 진행 모델로 너무 짧다**는 결정에 따라, 메이플 키우기의 **지역(34개) × 스테이지(1~10) × 보스(n-10)** 모델을 차용해 확장한다. 컨텐츠(몬스터·스토리)는 후속에서 채우고, **이 문서는 구조와 보스 배치도만 정의**한다.

---

## 1. 핵심 결정

### 3계층 진행 구조

| 계층 | 단위 | 갯수 | 역할 |
|---|---|---|---|
| **권 (Book)** | 동화책 1권 | 8권 (7권 + 히든 1권) | 큰 줄거리 단위, 각 권의 마지막 챕터 클리어 시 **장신구 슬롯 해방** |
| **챕터 (Chapter)** | 권 안의 진행 단계 | 권당 4~5개, **총 35챕터** | 운영·튜닝 단위, 각 챕터 안에서 적이 강해지는 곡선 |
| **스테이지 (Stage)** | 챕터 안의 분할 | 챕터당 10스테이지, **총 350스테이지** | 1세션 단위, n-10 = 보스 |

### 메이플 키우기 차용 패턴

- **n-10 = 보스 스테이지**: 챕터 마지막 스테이지에 그 챕터의 **메인 보스** 등장
- **n-5 = 미니보스**: 챕터 중간에 미니보스 (Little Hero 기존 `BalanceConfig.miniBossWaveInterval=5` 정합)
- **n-1 ~ n-4, n-6 ~ n-9 = 일반 스테이지**: 정규 적 무리
- 챕터 진행 시 적 HP/공격력이 지수적으로 상승 (스테이지 단위 + 챕터 단위 두 곡선)

### 보스 종류 3계층

| 종류 | 위치 | 등장 빈도 | 역할 |
|---|---|---|---|
| **권 보스 (Book Boss)** | 권의 마지막 챕터의 n-10 스테이지 | 8 | **장신구 슬롯 해방 트리거** |
| **챕터 메인 보스 (Chapter Boss)** | 모든 챕터의 n-10 | 35 | 챕터 클리어 보상 (별 조각 +N) |
| **미니 보스 (Mini Boss)** | 모든 챕터의 n-5 | 35 | 챕터 중간 진행 마커 |

권 보스는 챕터 메인 보스의 **부분 집합** (각 권의 마지막 챕터 메인 보스가 권 보스).

## 2. 설계 원칙

- **컨텐츠는 나중에**: 이 문서는 **구조** + **보스 배치도**만. 보스 이름·외형·HP·공격 패턴은 placeholder 또는 후속 문서.
- **메이플 키우기 영감 유지**: n-10 보스 모델, 챕터 안에서의 진행 곡선
- **Little Hero 정서 보존**: 동화책 8권의 큰 줄거리는 그대로. 단지 각 권을 4~5 챕터로 잘게 쪼개 진행 단계가 길어지도록.
- **MVP 정합**: MVP는 **책 1 (빨간 모자) 4 챕터 = 40 스테이지**만 다룸. 나머지는 콘텐츠 패치로 점진 도입.
- **시즌 무관**: 이 챕터 구조는 단일플레이 진행도. 시즌제(잭팟 ARPG Part 6)와 직교.

## 6. 데이터 모델 변경 사양

### 기존 `ChapterData` SO

3개 챕터(빨간모자/잭과콩나무/앨리스)가 SO 인스턴스로 존재. 이번 확장은 **3계층 SO 도입**으로 재구성.

### 신규 SO 구조

```csharp
[CreateAssetMenu(menuName = "LittleHero/Book")]
public class BookData : ScriptableObject {
    public int bookNumber;           // 1 ~ 8
    public string id;                // "book_01_redhood"
    public string displayName;       // "빨간 모자"
    public Sprite coverArt;
    public ChapterData[] chapters;   // 4~5개
    public string accessorySlotUnlockedOnBookClear;  // "Necklace" | null
    public bool isHidden;            // 책 8 = true
}

// 기존 ChapterData 확장
public class ChapterData : ScriptableObject {
    public int chapterNumber;        // 권 안의 번호 (1~5)
    public string id;                // "ch_01_01_outskirts"
    public string displayName;       // "마을 외곽"
    public int stageCount = 10;      // 1~10
    public EnemyData[] regularEnemyPool;
    public EnemyData miniBoss;       // n-5 스테이지
    public EnemyData mainBoss;       // n-10 스테이지
    public int starFragmentReward;
}
```

### 진행 추적 (`SaveData`)

```csharp
// 신규 필드
public int currentBook;          // 1
public int currentChapter;       // 1~5
public int currentStage;         // 1~10
public bool[] clearedFlags;      // [book * 100 + chapter * 10 + stage] 비트맵
```

또는 더 간단하게:

```csharp
public int highestClearedBook;
public int highestClearedChapter;
public int highestClearedStage;
```

(반복 클리어 카운트는 별도 매트릭스로 추적, 보스 반복 처치 드롭 빈도와 연결.)

### 마이그레이션 (기존 → 신규)

```
기존 Chapter_01_RedHood (totalWaves=20, bossEnemy=BigWolf, miniBossPool=[StarCloud])
  ↓
신규 BookData_01_RedHood
  ├─ Chapter_01_01_Outskirts (10 스테이지, mini=길고양이, main=큰 까마귀)
  ├─ Chapter_01_02_DeepForest (10 스테이지, mini=숲 정령, main=노련한 늑대)
  ├─ Chapter_01_03_WolfTracks (10 스테이지, mini=새끼 늑대, main=어미 늑대)
  └─ Chapter_01_04_GrandmaHouse (10 스테이지, mini=그림자 늑대, main=큰 늑대 아저씨 ★)
```

기존 `bossEnemy = BigWolf`는 마지막 챕터(`Chapter_01_04_GrandmaHouse`)의 `mainBoss`로 이전.

기존 `Chapter_02_Beanstalk`, `Chapter_03_Alice`도 같은 방식으로 분할.

## 7. MVP 범위

**MVP에 포함 (책 1 + 챕터 1만)**:
- `BookData_01_RedHood` 1개 (권 단위 SO)
- `Chapter_01_01_Outskirts` 1개 (10 스테이지)
- 일반 적 (기존 5종 재활용 + 색조 변형)
- 미니보스 1종 (1-1-5)
- 메인 보스 1종 (1-1-10)
- 권 보스 슬롯 해방은 **책 1 마지막 챕터까지 클리어해야 발동** → MVP에선 **책 1을 통째로 다 만들어야 슬롯 해방 검증 가능**
- → 권장: MVP는 **책 1 전체 4 챕터(40 스테이지) + 권 보스 = 큰 늑대 처치 → 목걸이 슬롯 해방** 까지 포함

**후속 패치**:
