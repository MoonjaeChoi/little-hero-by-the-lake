## 1. 핵심 결정

### 3계층 진행 구조

| 계층 | 단위 | 갯수 | 역할 |
|---|---|---|---|
| **권 (Book)** | 동화책 1권 | 8권 (7권 + 히든 1권) | 큰 줄거리 단위, 각 권의 마지막 챕터 클리어 시 **장신구 슬롯 해방** |
| **챕터 (Chapter)** | 권 안의 진행 단계 | 권당 4~5개, **총 35챕터** | 운영·튜닝 단위, 챕터 안에서 적이 강해지는 곡선 |
| **웨이브 (Wave)** | 챕터 안의 분할 | ✦ **챕터당 20 웨이브, 총 700 웨이브** | 1세션 단위, 5/10/15·20 = 보스 |

> ✦ 2026-04-30: 챕터당 10 스테이지 → **20 웨이브**로 변경. Little Hero 기존 시스템(`CLAUDE.md §6`의 "1챕터 = 20웨이브")과 정합. 메이플 키우기의 1~10 스테이지 구조를 차용했지만, 게임의 자동 사격(Auto-Shooter Roguelite) 정체성에 맞게 **웨이브 모델로 통일**.

## 2. 설계 원칙

- **컨텐츠는 나중에**: 이 문서는 **구조** + **보스 배치도**만. 보스 이름·외형·HP·공격 패턴은 placeholder 또는 후속 문서.
- **메이플 키우기 영감 유지**: 챕터 진행 모델은 차용하되, Little Hero 정체성에 맞게 **스테이지(1~10) → 웨이브(1~20)** 로 통일. 보스 위치는 W5/W10/W15(미니) + W20(메인) 4분할.
- **Little Hero 정서 보존**: 동화책 8권의 큰 줄거리는 그대로. 단지 각 권을 4~5 챕터로 잘게 쪼개 진행 단계가 길어지도록.
- **MVP 정합**: MVP는 **책 1 (빨간 모자) 4 챕터 = 80 웨이브**만 다룸. 나머지는 콘텐츠 패치로 점진 도입.
- **시즌 무관**: 이 챕터 구조는 단일플레이 진행도. 시즌제(잭팟 ARPG Part 6)와 직교.

## 6. 데이터 모델 변경 사양

### 기존 `ChapterData` SO

3개 챕터(빨간모자/잭과콩나무/앨리스)가 SO 인스턴스로 존재. 이번 확장은 **3계층 SO 도입**으로 재구성.

### 신규 SO 구조

```csharp
[CreateAssetMenu(menuName = "LittleHero/Book")]
public class BookData : ScriptableObject {
    public int bookNumber;           // 1 ~ 8
    public string id;                // "book_01_redhood"
    public string displayName;       // "빨간 모자"
    public Sprite coverArt;
    public ChapterData[] chapters;   // 4~5개
    public string accessorySlotUnlockedOnBookClear;  // "Necklace" | null
    public bool isHidden;            // 책 8 = true
}

// 기존 ChapterData 확장
public class ChapterData : ScriptableObject {
    public int chapterNumber;        // 권 안의 번호 (1~5)
    public string id;                // "ch_01_01_outskirts"
    public string displayName;       // "마을 외곽"
    public int waveCount = 20;       // ✦ 챕터당 20 웨이브 고정
    public float waveDuration = 20f;
    public EnemyData[] regularEnemyPool;
    public EnemyData[] miniBosses;   // ✦ 길이 3 (W5, W10, W15에 각각 등장)
    public EnemyData mainBoss;       // W20에 등장
    public int starFragmentReward;
}
```

> ✦ Little Hero 기존 `ChapterData` 필드(`totalWaves`, `enemyPool`, `miniBossPool`, `bossEnemy`)와 정합. `miniBossPool` → `miniBosses[3]` (위치 고정), `totalWaves` → `waveCount=20`.

### 진행 추적 (`SaveData`)

```csharp
// 신규 필드
public int currentBook;          // 1
public int currentChapter;       // 1~5
public int currentWave;          // 1~20
public bool[] clearedFlags;      // [book * 100 + chapter * 20 + wave] 비트맵
```

또는 더 간단하게:

```csharp
public int highestClearedBook;
public int highestClearedChapter;
public int highestClearedWave;
```

(반복 클리어 카운트는 별도 매트릭스로 추적, 보스 반복 처치 드롭 빈도와 연결.)

### 마이그레이션 (기존 → 신규)

```
기존 Chapter_01_RedHood (totalWaves=20, bossEnemy=BigWolf, miniBossPool=[StarCloud])
  ↓
신규 BookData_01_RedHood
  ├─ Chapter_01_01_Outskirts (20 웨이브, miniBosses=[m1,m2,m3], mainBoss=큰 까마귀 떼)
  ├─ Chapter_01_02_DeepForest (20 웨이브, mainBoss=노련한 늑대)
  ├─ Chapter_01_03_WolfTracks (20 웨이브, mainBoss=어미 늑대)
  └─ Chapter_01_04_GrandmaHouse (20 웨이브, mainBoss=큰 늑대 아저씨 ★)
```

기존 `bossEnemy = BigWolf`는 마지막 챕터(`Chapter_01_04_GrandmaHouse`)의 `mainBoss`로 이전.
기존 `miniBossPool = [StarCloud]`는 마지막 챕터의 `miniBosses` 슬롯 1개로 흡수, 나머지 2개 슬롯은 신규 SO로 채움.
기존 `Chapter_02_Beanstalk`, `Chapter_03_Alice`도 같은 방식으로 분할.
